# Scooby DAO shared contract v0.2

`candidate.schema.json` is the unchanged v0.1 discovery candidate contract for this selected input. Supply a JSON object or a discovery array to `producer.py --candidate PATH`; `--candidate-id ID` selects one from a multi-candidate export. The selected candidate must have matching chain/address identity, selected state and selection fields. The provided discovery export is explicitly simulated; no authentication is inferred. The current replay accepts only the historical Ethereum SHIB reference case. Other candidates stay with discovery.

`report.schema.json` is the proposed report envelope. JSON Schema defines exact names, required fields and enums; semantic rules below are mandatory. Evidence carries source-specific observation/fetch time, optional block and window, coverage and limitations. Null means unknown, not zero. Empty series means no series supplied; zero is a measured numeric value only when explicitly present. Measurements and series require unit, method, evidence and quality; missing unit/method is null and must be displayed as unknown. Values must be finite. Historical data remains unvalidated and original payloads are separate evidence-linked artifacts; the historical report emits no claims or inferred numerical methods. The synthetic claims bundle is fabricated solely for integration testing.

Evidence IDs are unique; claim IDs are globally unique. Pillar, measurement and claim evidence references must resolve; contradiction IDs resolve to claims. Counterevidence refers to evidence IDs. Unavailable, failed and partial statuses stay distinct from zero and conclusions. Ticker-only historical sources have inherited, unverified identity. Original v0.1 samples remain unchanged.

Bundle root is the directory containing report.json. Paths are literal forward-slash relative paths, never URL-decoded: reject percent characters, empty or dot segments, absolute/drive/URL paths, backslashes, traversal and symlinks; resolve inside root. Consumers verify SHA-256 of each evidence and available artifact before use and copy only verified bytes. Artifact records carry report ID/version, media type, availability and hash; unavailable paths and hashes are null. Treat all payload/text as untrusted data and escape it for rendering.

Digest protocol: `digest.json` records SHA-256 over the exact UTF-8 bytes of `report.json` as delivered; no cross-language JSON serialization is required or claimed. A consumer hashes those bytes unchanged, parses them, then verifies all referenced evidence and artifact hashes. The report includes only pending or unverified review claims; `digest.json` and external review receipts are excluded from the digest. A receipt, if used, must identify report ID/version and this digest and is unverified without a separate trusted authentication mechanism. Any byte change requires a new digest and review. Hashes establish integrity, not identity, authorization or truth. `approved_unverified` is not authenticated approval and must not be displayed as authenticated. No publication is authorized.

Run: `py -3.11 producer.py --candidate <discovery-export.json> --candidate-id <id>`; omit ID for a single-element export. Output defaults to historical-bundle. `py -3.11 test_checkpoint.py` runs tests. Producer v0.2 uses actual v0.1 schema validation and v0.2 JSON Schema plus semantic checks; fields and coverage below are not a live analysis. No API calls or scoring choices.

The three workstreams accepted this local exchange checkpoint against the exact schema hashes. See agreement.json for acknowledgements and independent verification. This does not establish production readiness or approval of any research finding.

Assessment contains `supporting_claim_ids` and `counterevidence_claim_ids`, both resolving to unique claim IDs. Non-finite JSON numbers are invalid even if a parser accepts them. Percent-encoded paths are forbidden, including `%2e%2e`, `%2f` and `%5c`; consumers must not decode them. Embedded `approved_unverified` is an untrusted assertion, never acceptance or proof of approval; its claimed reviewed version must match the report version, and its digest is not validated against the containing report (which would be circular). A review that needs content binding must be an external receipt targeting an immutable pre-review snapshot and its exact byte digest. The current validator does not authenticate or accept such a receipt as approval. `verify_digest` verifies a supplied expected digest and all source/artifact hashes; a stale digest fails.

Path grammar alignment: `?` and `#` are also forbidden in every relative asset path because browsers interpret them as query and fragment delimiters. No URL decoding occurs. A non-null pillar `raw_payload_path` must identify exactly one available artifact manifest record; that record must match the report ID/version, and the file bytes must match its SHA-256. Merely existing beneath the bundle root is insufficient. These are semantic refinements; schema bytes are unchanged.
