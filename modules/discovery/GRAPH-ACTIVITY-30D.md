# The Graph activity prefilter — local proof

`graph_activity_30d.evaluate` is an offline source-specific evaluator for one Ethereum Uniswap V3 token subgraph, profile `scooby.graph-activity-30d/1-proposal`. This is distinct from the selected-pool Gecko/CoinGecko profile. [Proposed schema](graph-activity-30d.schema.json). It never counts a concern-gate vote and does not claim all-protocol, all-chain or all-exchange token volume.

It binds canonical Ethereum token address, exact subgraph ID, fixed query and variables, captured response bytes/hash, indexed deployment/block/time, 720 closed UTC hourly buckets, and a separate named ECB-via-Frankfurter reference FX capture. It rejects GraphQL errors, indexing errors, a missing or stale indexed block, truncated pages, a mismatched token, duplicated/missing hours, malformed numeric fields and stale or mismatched FX. Graph `volumeUSD` is protocol-derived and can be affected by pricing or wash trading. Reported token-level TVL is not a pool execution quote. Optional volatility is historical realized hourly log-return sample standard deviation, annualized by sqrt(8760), distinct from VAE VaR. Neither indicator asserts safety. Indexed block metadata is not independently verified finality.

The complete indexed USD volume is multiplied by a *single* date-stamped reference INR/USD rate, not hourly or trade-time FX. The rate is requested for the day before the window-end UTC date or earlier, because a date-only rate does not prove an intraday publication time. `pass` is scoped to the indexed Uniswap V3 token data; `below_indexed_scope_threshold` cannot exclude the token globally. Missing data remain `unknown`.

`collect_graph_activity.py --candidate-id 1:0x... --output <new-directory>` is a **manual, one-shot** collector: at most one Graph request and one FX request, no retries, explicit new output directory, secret from `THE_GRAPH_API_KEY` in process or Windows User environment, Bearer header only, source capture hashes and request timestamps. It is not a recurring scheduler, not integrated into Cases, and does not provide a shared account-wide budget. Graph response errors, 429, an unavailable key, incomplete coverage or an hour boundary crossing cannot create a pass. The source does not provide Base coverage in this implementation. Keep any key out of URLs, logs and evidence.

## Bounded real source check

On 7 November 2026 IST the configured Graph key produced real source responses. Ethereum USDC, a technical reference rather than a suspected token, had 720/720 hours and passed for the indexed Uniswap V3 scope after a separate earlier-dated FX request. The original first attempt remains preserved with same-day-FX unknown; the corrected evaluation uses the same captured Graph response and a separately captured prior-date FX response. Artifact: `outputs/graph-activity-live-usdc-20261107/activity-replay-v3.json` in the discovery workspace; this schema-only replay preserves the actual earlier evaluation timestamp. This is not an investigation or evidence of the activity of all venues.

SHIB returned 704/720 hours; preserved offline replay remains unknown. Asentum returned zero matching hourly rows from this V3 subgraph; its known pool was a V2 pool, so this is only a V3 coverage gap. Neither result proves market-wide inactivity. These are point-in-time captured references, not recurring fresh evaluations. The parser was adjusted to handle The Graph's high-precision decimals and preserve exact indexed block number; original source captures remain unchanged.

Before merging or enabling this beyond an isolated reference, backend and frontend must agree a discriminated activity contract, server-owned capture/budgets, trusted time and indexing freshness policy, protocol/network coverage, pool versus token aggregation and missing-hour semantics. User-facing display must distinguish current checked results from historical examples and unknown activity; actual automatic investigation still requires four independently verified concern groups or authenticated human action.
