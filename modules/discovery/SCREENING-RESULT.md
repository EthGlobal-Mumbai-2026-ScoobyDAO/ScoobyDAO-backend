# Screening snapshot producer — proposal and integration handoff

This is an additive, local producer proposal, not the backend Cases API or a change to frozen candidate v0.1/report v0.2. Backend owns the read model, persistence, revisions, authenticated diagnostic authorization, bounded job dispatch and dispatch-time re-evaluation. Web must consume only the agreed backend contract and distinguish live records from historical replays and synthetic demonstrations. This module does not itself deliver candidates to `/cases` or initiate research.

## Now

Call `screening_result(record, evidence_root, run_id, as_of)` with a live candidate record, the root containing its `snapshots/`, and a safe run correlation identifier. `as_of` must be timezone-aware; omitting it uses the current UTC time. The caller-supplied run ID does not establish that a durable run exists. The return value is a point-in-time proposal with candidate chain/address, a versioned policy, 12 concern outcomes, measurements and evidence references, observed and fetched times, finalized block number/hash, coverage, disposition, attention reasons and a SHA-256 snapshot ID. The digest covers compact UTF-8 JSON of every other field, sorted by key with no ASCII escaping, using separators `,` and `:`; it is an integrity identifier, not an authenticated signature. Verifiers independently inspect data; the hash alone is not a source correctness proof.

Only the code-pinned G07 and G09 verifier functions can produce votes. They are limited to a single Ethereum Uniswap V2/WETH pool; the G07 sampled LP-address measurement is not beneficial ownership, and G09 covers price but not volume. Observed and fetched timestamps must both be within the provisional one-hour window and fetched cannot precede observation. The adapter checks the candidate chain/address, file hash, block/finality and provenance again. A shared evidence digest across triggered groups causes all those votes to become unknown. Distinct hashes are necessary but not sufficient for causal independence; new verifiers require review for correlated measures, independently scoped evidence, tests and a new policy version. Unsupported, unverified, held, stale or invalid data cannot vote. Provider hints do not vote.

`auto_eligible` means the snapshot meets the four-distinct-concern policy; it is not a job, human approval, report approval, fraud finding or probability. `human_review_required` means at least one verified concern but fewer than four and indicates a possible diagnostic request, not qualification. `monitor` has no verified trigger. These producer labels are not the backend's proposed Cases lane enum and must be mapped by backend alongside actual job and authorization state. Because there are only two pinned groups, auto eligibility is unreachable on this version; no qualifying fresh candidate is claimed. Never enable more groups or lower the threshold merely to fill the board.

## Next and rollout

Agree a producer/consumer contract with backend, including durable run/snapshot association, evidence storage and access, freshness, independence and replay labeling. Backend must recompute from trusted candidate/evidence on the server with its own current clock immediately before dispatch, verify the policy and identity, enforce request/cost budgets and concurrency, and keep diagnostic authorization separate from the four-concern gate and final report review. Do not accept a client-supplied snapshot, caller-provided `as_of`, or claimed actor string as authority. Keep output read-only and unused by the worker until these boundaries and durable state are implemented. Rollback is to stop invoking this additive producer; no storage migration is introduced.

## Verification

`python -m unittest -v test_screening_result.py` exercises synthetic historical fixtures only, including actual G09 verifier invocation, evidence digest/timestamps/block identity, corruption, stale and future data, unsupported replay, provider hints and correlated artifact controls. These tests neither perform network requests nor create a real qualifying case. Additional integration tests must verify concurrent updates, durable snapshot ownership, server-time revalidation, authorized diagnostic actions and bounded dispatch before use in production.

## Reddit leads

`reddit_leads.adapt` consumes the investigation-owned `scooby.reddit-leads/1` provider result without network or storage. The caller supplies a query/community allowlist, an explicit window, and provider budget no greater than five requests, 40 posts and three subreddits. It returns bounded transient post IDs/URLs, source times, query, extracted address/ticker mentions, coverage states and informational cursors. The callable currently cannot resume from those cursors. The output intentionally excludes excerpts, content hashes, provider error strings and credentials. Duplicate posts and matching address/chain mentions are grouped; these groupings never imply independent corroboration.

Sources expire at the earlier of one hour after fetch or seven days after posting; the caller must supply removal notifications and enforce deletion/TTL on all downstream state. The adapter cannot independently detect source changes or deletions. Never copy Reddit excerpts or hashes into candidate evidence, immutable case snapshots or report bundles. Failed, unavailable, truncated and empty source states remain distinct and never yield votes; no fallback scraper exists.

`resolve_identity` requires exactly one mentioned EVM address and an explicit unambiguous supported chain mention, then re-runs the pinned on-chain verifiers over a trusted server-owned candidate/evidence bundle. Chain-bound finalized-block evidence establishes token identity; the source's allegation and its connection to that token remain unverified. No user-supplied result or social assertion can produce concern votes. Current verifiers support Ethereum V2/WETH only. Backend owns the trusted candidate bridge, independent server-time revalidation, durable TTL/deletion state and actual Cases read model. `deduplicate_resolutions` groups already-resolved leads by canonical chain/address without copying votes or asserting corroboration. The invented historical fixture `fixtures/reddit-lead-synthetic.json` plus offline tests demonstrate the boundary; do not load it as live data.

The root team's one unauthenticated Reddit search request received HTTP 403 with no credentials and no records ingested; its exact cause is unknown. Authorized search and subreddit availability remain unproven. Provider owner retains OAuth/transport, shared budget and rate-limit handling.
