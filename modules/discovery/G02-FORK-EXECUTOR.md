# G02 local-fork executor — experimental handoff

This tool is an **unwired prototype** for one Ethereum/Base Uniswap-V2-compatible WETH → token → WETH path. It implements a stateful sequence against an already-running, dedicated local Anvil fork. It is not a G02 verifier, does not classify a revert, does not select a candidate, and always returns `gate_status: unknown` and zero votes. Nothing in this handoff establishes a token verdict.

## What it does

- Accepts only numeric loopback HTTP (`127.0.0.1` or `::1`) without URL credentials, path or redirects; environment proxies are disabled. It checks the Anvil client string, fork metadata, chain ID, pinned number/hash and an unadvanced head before local mutations. Anvil's expected metadata shape is `forkedNetwork.{chainId,forkBlockNumber,forkBlockHash}` and has **not yet been checked against a real installed version**. A local server that lies about its identity is outside this check's trust boundary.
- Checks code is present, records SHA-256 of the token/WETH/pool/router runtime bytes, checks the pool assets, nonzero reserves, router/pool factory agreement and factory pair lookup. Code hashes are not source matches or proof of runtime correctness.
- Generates a new local-only actor, takes an Anvil snapshot, impersonates and funds that actor locally, wraps native currency, approves WETH, buys, approves the purchased token and sells it for WETH. The transaction sequence, balance/allowance readings, receipts, raw-unit amounts, explicit funding/impersonation overrides, gas limit, deadline and minimum outputs are recorded. It tries `debug_traceTransaction` for buy/sell and failure cases; a missing trace is unknown.
- Rechecks the anchor, stops impersonation and reverts the snapshot. A bad postcheck or failed cleanup cannot be reported as a completed run. The JSON-RPC transcript is hash-addressed in `result.json`; local RPC attempts have an explicit cap with three calls reserved for the postcheck and cleanup. Metadata responses are redacted because the fork URL may include credentials. RPC error messages are not persisted.

`completed` means only that the local transactions completed and a positive WETH balance delta and complete token spend were observed under the stated conditions. `sell_incomplete`, `sell_partial`, `sell_zero_received`, and setup failures are observations or missing coverage, not automatic transfer-restriction classifications. A call-level success with no economic proceeds is not treated as a complete sell.

## Required deployment and policy boundaries

No Anvil, Forge, Solidity compiler, Docker, `eth-tester` or `py-evm` was found on this machine during the offline check. Install a compatible local Anvil version and supply a separately authorized archive RPC/fork before attempting real EVM validation. No installation, fork, archive request, real transaction, wallet use, model call, or live test was performed for this patch. The executor itself talks only to loopback, but an Anvil fork can make **upstream archive requests on demand**. The caller must enforce and report that external budget independently; `max_rpc_calls` limits only local JSON-RPC calls and is not an upstream request counter.

Use a fresh, dedicated, isolated local fork per job, with no other clients. A matching initial header/metadata cannot prove the fork has not been altered, and this prototype does not lock the node against concurrent clients. Treat failed cleanup, process termination, or an unknown node state as grounds to discard the entire fork. The exception-safe cleanup cannot run after a forced process kill. The backend owns job authorization, isolation, endpoint lifecycle, request/cost budgets, durable artifacts and scheduling; never point the executor at a nonlocal endpoint.

The investigation profile `scooby.mechanism-observations/1` is a draft. This output is **not** that profile, does not claim reviewed state lineage, and cannot authenticate its own EVM execution, source, control-path or trace semantics. An independently validated adapter must map artifacts and declared overrides without marking them reviewed merely because hashes or receipts exist. A restriction signal requires coherent replay, appropriate trace/source/controller attribution and ordinary-failure controls; direct isolated calls and provider labels are insufficient. Known-sellable controls, different ordinary actors/sizes, reset/repetition, counterevidence, route compatibility, gas, allowance, slippage, launch state and ordinary taxes remain required by the investigation protocol. Additional *distinct* concern groups are still necessary for the four-group gate.

## Plan and invocation

The JSON plan uses profile `scooby.g02-fork-plan/0` and **exactly** these fields: `candidate_id` (`1:` or `8453:` plus lowercase token address), lowercase `pool` and `router`, `block` with integer `number` and lowercase 32-byte `hash`, base-unit decimal strings `amount_in`, `minimum_buy_out`, `minimum_sell_out`, `native_funding`, integer `deadline`, integer `gas_limit`, and integer `max_rpc_calls` (35–120, including cleanup). The caller must choose explicit route, amounts, minima and budget from verified context; no amounts or live credentials are embedded here. Zero minimum outputs are technically accepted and must be treated as an explicit scenario limitation.

After a source budget and suitable isolated fork have been authorized and prepared, invoke `python g02_fork_executor.py --plan <plan.json> --endpoint http://127.0.0.1:<port> --output <new-directory>`. The directory must not exist. No upstream endpoint or credential should be put in the plan, output path or command line.

## Verification performed

`python -m unittest -v test_g02_fork_executor.py` uses a mocked, in-memory RPC state machine. Its controls exercise ordering, balances, no-vote semantics, local-only endpoint validation, wrong fork metadata, sell/buy failure, partial sell, trace capture, credential redaction, bad anchor postcheck, budget cleanup, lost impersonation reply and cleanup failure. The independent local Keccak check matched the function selectors used by the implementation. **These tests are not EVM execution**, and actual Anvil version compatibility, fork state semantics, adversarial contracts, trace review and end-to-end integration remain unverified.
