# Producer-to-renderer acceptance seam

This is a component-level synthetic contract test, not acceptance of the complete scouting journey. The fixture represents produced `scooby.reasoning/2` and five pillar IRC data; it does not call a research producer, World ID, a model, a source or a wallet. The test uses the current local diagnostic-exception route solely to attach the fixture to a test run. That route is not user authorization and does not qualify a scout. The existing investigation worker still reports pillars unavailable; manual fixture import is not automatic research.

The current seam checks exact report digest; candidate-to-run match; cross-candidate and tampered-evidence rejection; pending review; report ID, version and run association; report library visibility; HTML digest, synthetic provenance, five pillar/IRC blocks and source anchors; and, when `SCOOBY_BROWSER` is set, PDF digest, synthetic recommendation, counterevidence, reversal, no URI annotations and resolving internal destinations. Node is optional for the DOM assertions; absent Node means that portion does not run. PDF evidence bytes remain in the matching companion bundle. Renderer never changes final sign-off state.

When the producer/backend implementation lands, run the same checks against its actual committed bundle and new Case-to-run-to-report API, in both automatic and verified-human lanes. Add negative authorization, expiry, replay, failed/partial, retry and cross-case tests at those owner boundaries. A case should expose its exact run, report version and digest; the Reports entry and both artifacts must refer to that same report and preserve reference/synthetic/source provenance. Existing report schema v0.2 stays frozen; identity linkage belongs in the separately coordinated case/run/report orchestration interface, not an invented report field.

The fixture contains no plotted time series, so this test does not validate generated graph geometry or 375-pixel browser layout. The integrated application still needs a real producer-backed chart fixture and the narrow/browser, physical keyboard, screen-reader, all-page reading-size and target-container checks. The two full product journeys and World ID action binding remain open; no live calls or deployment are authorized by this test.

Run locally with `SCOOBY_BROWSER` set to an installed Chromium executable, `SCOOBY_MODEL_CALL_BUDGET=0`, and `python -m pytest tests/test_bundle_artifacts_contract.py`. The browser-enabled test is required to exercise PDF; without it the test asserts PDF unavailable rather than claiming PDF success.

## Captured-producer replay

An existing hash-validated, no-network historical discovery replay (report SHA-256 `084b6c12efce1987aa729cfbb194c729b3fd8dcbeef1a931b9a171f62eea0d53`) exposed hidden partial-status labels and a missing assessment summary when no reasoning sidecar was supplied. The reader now shows partial and unavailable coverage, source-linked fallback summaries and labeled citations; it renders the report assessment summary and unknowns without inventing a conclusion. Hash-verified means byte integrity, not independent factual verification.

On the captured replay, the builder verified every report-bound asset hash; Edge at 1440 and emulated 375 CSS pixels showed five sections, three partial/two unavailable, 15/15 resolving citation anchors, an opening claim disclosure, and no overflow. No series were supplied, and no charts were fabricated. A 15-page local test PDF had 38 resolving internal links, zero URI annotations and 30/30 selected claim/summary/Markdown text items. All pages were reviewed as reduced-size contact sheets, not all at reading size. The historical replay uses a synthetic World authorization reference; it is not a verified World action, live investigation, production report or composed Case journey.

To repeat the opt-in actual-bundle test without committing captured source data, set `SCOOBY_CAPTURED_BUNDLE` and `SCOOBY_CAPTURED_REPORT_SHA256`, then run `python -m pytest tests/test_captured_bundle_contract.py`. It verifies the expected digest, reader contract and DOM when Node is available. The test is skipped if no bundle is supplied; it is not a substitute for browser, PDF or full-product checks.
