# Graph activity read boundary — draft

`GET /scouting/cases/{case_id}/activity` reads a case-bound, server-owned Graph token-hour capture and returns `source_type=graph_token_hour`, `decision_scope=ethereum_uniswap_v3_token` and `gate_effect=none`. `pass` or `below_indexed_scope_threshold` is limited to that indexed scope, never global token activity or a case qualification. The result uses 720 closed hours ending at the last closed hour and a single dated ECB-via-Frankfurter rate. Values remain provider estimates and are not independently authenticated source facts.

A trusted local operator can run `python graph_activity_read.py CASE_ID --capture-status ... --fx-status ... --graph-bytes ... --fx-bytes ...`; there is no HTTP path for capture installation or calls to Graph/FX. The server verifies exact candidate/query/bytes, saves append-only content-addressed input records and recomputes from raw captures using its clock for every read. A valid result carries `valid_until_utc`; after the earliest source/FX/index freshness limit or the next hour boundary it returns unknown. No capture or malformed data yields unknown or an integrity error, not zero. The input import relies on local operator provenance and does not independently authenticate the provider. No secret-bearing URL is accepted, and the result never authorizes the four-group gate or World case/report review.

The manual collector remains separate, one-shot and not integrated with scheduled scouting. Budgets and rate limits must be bound separately before any production collection. This is not a token-wide filter, a source-truth guarantee, or a public release of a report.
