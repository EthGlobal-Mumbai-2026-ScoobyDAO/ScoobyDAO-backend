# Case orchestration: local vertical slice

This is an additive runtime API, not a change to shared candidate v0.1 or report v0.2. The teammate-owned research authorization and publication/sign-off integrations are separate. The existing World ID publication module does not authorize case research. See the separately proposed [scouting qualification charter PR](https://github.com/EthGlobal-Mumbai-2026-ScoobyDAO/ScoobyDAO-backend/pull/10); it is not a merged authority contract.

`GET /scouting/cases` (alias `/cases`) returns actionable `scouting-case-list/2`; `/scouting/schema` supplies its schema and digest. V1 is retained as an older read contract, with explanation fields optional. V2 requires source-grounded scouting clues, verifier names/measurements, freshness and routing rationale. It ranks all cases before returning 100: more fresh verified concern groups rank ahead, and a concrete unverified provider concern raises review urgency within an equal verified tier. This is a deterministic triage key, not a probability or a gate vote. Above 5,000 records the API returns 503 rather than a misleading truncated ranking. The local operator API is unauthenticated and must not be publicly exposed.

`POST /scouting/cases/refresh` queues bounded reconciliation of configured local discovery snapshots. Four distinct fresh, independently verified concern groups are required for automatic admission. Decision bindings, source/model budgets, evidence hashes, expiry and deduplication are checked before the durable run is created. Current built-in verifiers cannot produce four distinct positive groups, and discovery captures may be stale; unknown does not mean safe.

For human judgment, a case-scoped challenge binds candidate, snapshot, policy, intended `diagnostic_research` action, nonce and expiry. `POST /scouting/challenges/{id}/world-attempt` starts the World device grant; `GET /scouting/world-attempts/{id}` polls it, and `POST /scouting/world-attempts/{id}/cancel` cancels a pending attempt. A validated World token plus an explicitly configured server-side case-admin authorizer permits one atomic challenge consumption and investigation enqueue. No production admin authorizer is implemented, so this path fails closed even if World credentials are present. Denied, expired, cancelled, superseded and replayed attempts do not create a run. World or admin authorization configuration absent returns 503; the client must show the case and intended action before starting the grant. This authenticates the human for a server-bound action and is separate from final report review/publication. Device codes remain in process memory; a restart expires pending attempts. World ID and verifier injection tests are synthetic and do not demonstrate live confirmation.

Both admitted lanes call the same `modules.investigation.case_research.run_case` producer via `case_jobs.py`. The worker verifies snapshot, policy, decision and human binding, enforces the decision's zero-source/zero-model budget, validates the resulting frozen v0.2 bundle and case/run/authorization lineage, imports a partial draft, updates pillars, and queues the existing HTML/PDF renderer. Case detail exposes run and report identity; `/reports` lists generated reports and separately scoped references. If the authorized budget and captured inputs yield no usable evidence, the run is `blocked` and no empty report is presented as complete. The producer can replay immutable hash-bound discovery snapshots with zero external requests and original timestamps; reused live observations are labeled historical replay. Runs without usable captured evidence remain blocked; no extra provider calls are authorized. A `POST /reference-runs` import remains separate and queues no investigation. Candidate and report frozen schemas remain unchanged.

Investigation adapters for Reddit and token contracts are being prepared in PR [#11](https://github.com/EthGlobal-Mumbai-2026-ScoobyDAO/ScoobyDAO-backend/pull/11); this backend does not invoke them. Investigation's broader 365-day query returned seven historical context records; the optional read-only metadata seam below exposes these as unresolved, with no gate votes. A separate candidate-specific provider error establishes neither sentiment nor a general source outage. No provider key triggers requests here. The backend does not persist post IDs, excerpts, URLs, hashes or derived content; durable retention and linkage require a reviewed lifecycle. The externally managed metadata file has its own separate deletion responsibility. No real Reddit, source, model, World/chain or publisher calls occur in this backend slice.

Tests: `python -m pytest -q tests/test_cases.py` uses bounded local SQLite, synthetic evidence and patched verifier results for the four-group lane. It checks source failure/unknown, global ordering >100, dedup across delivery and changed snapshots, evidence/assessment/policy tampering, expiry, human fail-closed, a reference-only lane and actual verifier unknown behavior. A mock verifier is test-only and never registered in runtime. Before any real producer is wired, add race/crash/fencing, full cursor pagination, credential adapter/replay/revocation, budget and security tests.


### Transient social context

`SCOOBY_SOCIAL_CONTEXT_FILE` optionally points to the investigation owner's externally managed `scooby.reddit-leads/1` metadata file. `GET /scouting/leads` reads and projects up to 40 records on demand; nothing is copied into the case database or report snapshots. The view is unavailable after 24 hours from fetch, when the file is removed, or when validation fails. Operators must arrange deletion of the external file independently; expiration of the view does not delete it. SearchApi status is partial when valid metadata is present. Attribution is always unresolved and concern votes are always zero; historical context cannot qualify a case. The backend does not initiate provider requests. Durable retention/deletion and identity linking are not implemented.

Up to three external metadata feeds can be configured with `SCOOBY_SOCIAL_CONTEXT_FILES` (OS path separator). Each is validated and expires independently; unavailable feeds do not hide usable feeds. `SCOOBY_SOCIAL_CANDIDATE_STATUS_FILE` optionally supplies separately managed candidate-query failure metadata for `GET /scouting/social-candidate-status`. A provider-declared error is reported as unavailable, not as a zero-result or sentiment finding, and does not change the general source status.

Case cards include `scouting_clues`, drawn from hash-bound discovery triggers and a narrow allowlist of captured GoPlus claims. The claims remain unverified and do not vote. `reasons` include verifier names and any recorded measurements; `routing_rationale` states the independent gate and human-verifier requirements. `evidence_freshness` describes the captured timestamps, not safety. The additive DTO fields change the runtime schema digest and require client coordination; frozen candidate and report schemas are unchanged.

Admin-only report sign-off is a separate checkpoint and is not implemented for generated drafts by this case workflow. Existing local review records are unauthenticated and cannot satisfy that requirement. No automatic publication occurs.
