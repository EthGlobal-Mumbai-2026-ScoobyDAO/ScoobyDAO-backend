# Case orchestration: local vertical slice

This is an additive runtime API, not a change to shared candidate v0.1 or report v0.2. The teammate-owned research authorization and publication/sign-off integrations are separate. The existing World ID publication module does not authorize case research. See the separately proposed [scouting qualification charter PR](https://github.com/EthGlobal-Mumbai-2026-ScoobyDAO/ScoobyDAO-backend/pull/10); it is not a merged authority contract.

`GET /scouting/cases` (alias `/cases`) returns `scouting-case-list/1`; `GET /scouting/schema` returns its standalone schema and digest. It ranks the whole local index before showing the first 100: human-action-required first, then auto-qualified, research-running, monitoring and unavailable; within lanes fresh independently verified concern count descends, candidate ID breaks ties. `priority_order` is a deterministic sort key, not a calibrated score. `truncated` is explicit. Above 5,000 records the list fails with 503 rather than silently excluding urgent cases; indexed cursor pagination is future work. Detail routes are `GET /scouting/cases/{case_id}` and `/cases/{case_id}`. Per-case source observation timestamps and unknowns remain explicit; running/incomplete/pillar states come from persisted runs, not static progress. HTTP is local/operator-only and unauthenticated; CORS GET is not an authorization control.

`POST /scouting/cases/refresh` with `Idempotency-Key` and `{\"limit\":1..25}` enqueues local read-only reconciliation. Set `SCOOBY_DISCOVERY_DB` and `SCOOBY_DISCOVERY_ROOT` to the discovery-owned local database and snapshot root. `SCOOBY_CASE_SYNC_ENABLED=true` opts a separately running worker into a once-per-minute bounded local reconciliation (default off; max 25, one queued/running job). The bridge does not launch live collection. Discovery owns upstream scouting and PR [#9](https://github.com/EthGlobal-Mumbai-2026-ScoobyDAO/ScoobyDAO-backend/pull/9); the backend re-runs `review_queue.assess` on captured hash-checked snapshots and binds candidate/evidence/assessment/policy digest, freshness and decision. Four distinct fresh independently verified triggered groups are required; five increases priority. Only G07 and partial G09 are presently registered, so no real candidate can auto-qualify through current modules.

A qualified decision creates a durable `case_start` job; at execution, freshness, candidate/snapshot/policy and actual verifier results are checked again. One SQL transaction deduplicates a candidate's investigation and creates five pillar rows and an investigation job. A changed snapshot cannot repeatedly create runs for a candidate; explicit supersession/cooldown is not implemented and new runs remain suppressed. The decision has an enforced-by-current-implementation zero external-source / zero model-call allowance: the existing worker has no research producer and records each pillar unavailable, then the run incomplete. Runtime enforcement for future producer wall time, token and network budgets is still required. This is durable orchestration and fail-closed scaffolding, not a complete investigation.

Ambiguous/exception candidates may request a challenge with expected revision, idempotency key and `diagnostic_research` action. The challenge binds candidate, snapshot, policy, nonce and expiry; snapshot changes supersede it. All continuation/deny/revise/revoke operations fail closed until a separately owned authenticated credential adapter verifies those bindings, one-use/replay and revocation. Legacy unverified live investigation start, resume and reasoning paths are blocked. Historical synthetic tests remain separate. `POST /reference-runs` creates a no-job container for a separately authorized manually authored reference import; it grants no research, gate qualification, human authentication or publication.

Investigation adapters for Reddit and token contracts are being prepared in PR [#11](https://github.com/EthGlobal-Mumbai-2026-ScoobyDAO/ScoobyDAO-backend/pull/11); they are not invoked here. Reddit's source status is unavailable. No post IDs, excerpts, URLs, hashes or derived content are retained until an approved deletion/retention lifecycle exists; lead dedup/linkage is consequently blocked. A Reddit mention, social sentiment, scanner flag or unresolved address never votes. No real Reddit, source, model, World/chain or publisher calls occur in this slice.

Tests: `python -m pytest -q tests/test_cases.py` uses bounded local SQLite, synthetic evidence and patched verifier results for the four-group lane. It checks source failure/unknown, global ordering >100, dedup across delivery and changed snapshots, evidence/assessment/policy tampering, expiry, human fail-closed, a reference-only lane and actual verifier unknown behavior. A mock verifier is test-only and never registered in runtime. Before any real producer is wired, add race/crash/fencing, full cursor pagination, credential adapter/replay/revocation, budget and security tests.
