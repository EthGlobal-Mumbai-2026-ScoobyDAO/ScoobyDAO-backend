# Authorized Graph case input and report list

The investigation producer's Graph verifier handles the native captured Ethereum V3 `tokenDayDatas` source and separately verifies any saved, same-candidate VAE run. It makes no source request and does not choose or change the saved historical horizon. These token-level USD observations are not selected-pool candles, do not establish market-wide coverage, and are not evidence that model outputs are calibrated.

`case_graph.install(...)` is a server-internal interface, not an HTTP route. It requires a server-owned administrator authorizer returning an unexpired receipt for the exact binding digest; none is implemented for production, so installation fails closed by default. A browser path or Boolean is never accepted as authorization. The proposed `scooby.graph-source-selection/1` record names the exact candidate, source type, deployment, window, selection rationale, discovery status and evidence hashes, including the capture manifest. Raw selection evidence is bounded, hashed, checked for credential-bearing content and kept privately. `discovery_status: not_provided` is explicit; do not infer source discovery from a saved capture.

The binding is immutable per decision and includes the case, candidate, snapshot, policy, exact file inventory and hashes, source selection, optional supplemental digest, and explicit historical horizon matching the saved model manifest. A separately verified admin may renew the same binding, but cannot silently replace it. Before work, `case_jobs.py` rechecks authorization, copies and rehashes the private input into a temporary per-attempt directory, and invokes the producer with those exact paths. Graph evidence source status, row/missing counts and coverage limitation stay separate from case qualification. Unsupported or zero-row source data is not an absence verdict. No Graph request or model training happens here. Human case confirmation, source authorization and final report sign-off are separate boundaries.

`GET /reports` provides a bounded-summary view of existing report identity/version, case/run lineage, provenance/mode, observed/fetched times, actual per-pillar status and quality issues, unverified local review and an explicit unavailable consumer-release state. It is a local operator prototype with no pagination yet and is not a consumer release API. `GET /reports/{id}/{version}/artifacts` distinguishes queued/running/failed/cancelled rendering from missing artifacts; an unavailable PDF does not invalidate an available HTML draft. Reports remain pending until the separate admin review and release workflow exists.

Tests use synthetic admin receipts and data, exercising exact binding, mutation/expiry rejection and six distinct partial reports without provider/model/chain calls. These are not real admin verification or six complete live reports. The current source-adapter receipt verifier and admin/private access boundary remain unimplemented.
