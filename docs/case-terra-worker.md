# Bounded case Terra worker

`SCOOBY_CASE_MODEL_MAX_CALLS` is a server-owned policy, `0` by default and at most `1` per new case decision. The case decision binds this budget into the policy digest; the API cannot choose a budget, older decisions cannot be widened, and API/worker processes must use the same configuration. Source requests remain zero. The worker can replay validated, timestamp-preserving discovery snapshots with no network calls. This configuration is not an authorization to spend or publish.

With a budget of one, the shared producer makes at most one `gpt-6.1-terra` Chat Completions structured-output request for all five pillar analyses and the conclusion. It uses app-owned evidence, a 120,000-character context limit, 4,096 completion-token limit, no provider retry, and no model tools. Per-pillar events describe validation of one shared output, not five agents or five calls. Frozen source facts, input IDs and unavailable VAE/coverage remain explicit. Model output is a proposed interpretation; report approval and publication remain separate admin actions.

`case_model.Ledger` atomically reserves the attempt immediately before transmission. It binds the case run, immutable decision and evidence revision, requested model, prompt and response-schema hashes, input hash and caps. A completed validated checkpoint and reported token usage are stored durably; a matching checkpoint can be reused without another call after a crash. Reserved, failed, cancelled or ambiguous attempts consume the one-call allowance and are never automatically retried. If source/policy changes or the run is cancelled, the stage does not proceed. Missing credentials, refusal, incomplete output, identifier mismatch or invalid/unlinked output remain explicit; absent provider usage is not estimated. Reported usage and safe status codes may appear in event metadata; prompts, source bytes, credentials and hidden reasoning do not.

`GET /investigations/{run_id}/events` returns ordered `{seq, run_id, kind, detail, created}` rows. `detail` is a JSON-encoded string for `research_stage_*` and `model_stage_*`; it carries stage/state, allowed source/pillar name, model/caps/budget on the one reasoning start, and reported usage or a safe failure reason when available. A budget-zero run emits `model_stage_skipped` with `model_budget_zero`; source preparation events do not imply model calls. Progress and report drafts never imply World confirmation, administrator authorization, final sign-off or publication.

The two case routes and model stage are exercised through injected synthetic clients and captured synthetic evidence. No live model call is made by tests. The live World case path still fails closed until a real server-side admin authorizer is implemented. Existing report review and publication paths are separate and require their own admin boundary.

The producer projects bounded source observations into typed input IDs before analysis. Cross-pillar context requires linked citations and a local pillar anchor; numeric formatting is checked against supplied evidence. When grounding fails, the stage stays failed and the backend records only a fixed diagnostic category (for example `pillar_citation_scope_invalid` or `unsupported_numeric_literal`), never model prose, raw IDs or numbers. Prompt, schema, source and policy changes invalidate prior checkpoints. A separately authorized SHIB completion was rejected under an earlier validation contract; it was not installed, and updating the contract does not authorize a second call or retroactively validate it.
